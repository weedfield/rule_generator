## プロジェクト固有: git-web / git-web-edit

### マークアップ
- デモのソースを Source パネルから取得しているか(DevTools からは極力 HTML を取得しない。不要な要素も一緒に取得してしまうため)。
- 開発接続用のコメントが入っているか。
  - 既存画面が存在する場合 → 変更箇所を FACE-XXX で囲んでいるか:
    ```
    <!-- ↓↓↓ FACE-XXX backlog案件名 ↓↓↓ -->
    <!-- ↑↑↑ FACE-XXX backlogの案件名 ↑↑↑ -->
    ```
  - 新規画面の場合 → 変更箇所を MEMO でコメントしているか(参考):
    ```
    <!-- MEMO:id追加/class追加/カセット1つめ、など -->
    ```
- img, input, br などの空要素の最後に / をつけたか(✗ `<img>` / ◯ `<img />`。JSP コーディングルールより)。
- デモにパターンを網羅できているか(カセット要件が複数ある場合や、電話番号あり/なし など)。
- ログ関連の suumo.jp 本番パスを検品パスに修正できているか:
  - `//suumo.jp/front/tag/stmt/stmt_sp.js`
  - `//suumo.jp/sp/js/s_code_prd.js`
  - `//suumo.jp/sp/js/catalyst.js`

### 差込ファイル
- (可能な範囲で)差し込みファイル内だけで完結するモジュール設計になっているか。
- 改行コードは CRLF になっているか(既存に合わせる)。
- インデントはタブになっているか(既存に合わせる)。
- 命名規則に則った差し込みファイル名になっているか / 事前に決めているか。
- コメントが下記のとおり書かれているか(この3行はインデントなし。= は長さが足りなければ他の差し込みファイルに合わせる):
  ```
  <!-- ↓============================================↓ -->
  <!-- ↓/detail/KR_100_000_CF_kaisha_seoparts.html↓ -->
  <div class="l-section_h2"> </div>
  <!-- ↑/detail/KR_100_000_CF_kaisha_seoparts.html↑ -->
  <!-- ↑============================================↑ -->
  ```
